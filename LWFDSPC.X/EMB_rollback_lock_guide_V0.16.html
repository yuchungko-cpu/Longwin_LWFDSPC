EMB 倒溜鎖定 — 調參數說明

使用者版  |  專案 LWFDSPC  |  2026-07-31  |  所有參數皆為 #define，修改後需重新編譯燒錄才生效

本文只講倒溜鎖定這一條路徑。EMB 的整體狀態機、IEMB 故障偵測、停車上鎖延遲請看同目錄的 EMB_parameters_guide.html 與 EMB_tuning_guide.html；那兩份文件寫於本功能加入之前，不包含本頁的內容。

0規格與現況

設計規格：命令前進、車卻後退時，倒溜量不得超過 1/4 車輪。
1/4 車輪 = 91 個霍爾邊緣 = 159 mm ≈ 16 cm（8 吋輪，周長 638 mm，365 邊緣/輪轉）

目前設定：連續 3 個反向霍爾邊緣就鎖定，也就是倒退約 5 mm（0.5 cm），離規格上限有 30 倍餘裕。

1 個霍爾邊緣車輪 1.75 mm1/365 輪轉馬達 20°
鎖定與車速無關。用「邊緣數」而不是「速度」當條件，所以再慢的潛行倒溜也會在同樣的位移被攔下 —— 這是能保證上述規格的關鍵。

1先分清楚：兩種倒溜走不同的路

有動力倒溜本文主題無動力倒溜
情境油門踩著，坡度大於馬達扭力，車被重力拉著後退（上坡起步）沒踩油門，車停在坡上被重力拉著滑，或被人推
EMB 狀態RELEASED（煞車已放開，馬達在出力）WAITING_TO_LOCK（正在等上鎖）
偵測方式連續 N 個「與命令方向相反」的霍爾邊緣UVW 短路後，轉向與先前行駛方向相反（Plan B）
動作立即鎖定 + 閂鎖到鬆油門立即鎖定（不閂鎖）
參數本文第 3 節無可調參數（純方向比對）

另外還有兩條與倒溜無關的上鎖路徑：UVW 短路後延遲上鎖（正常停車）、命令歸零逾時 failsafe（霍爾異常時的保命線）。見 EMB_parameters_guide.html。

方向怎麼判斷的：uGF.Direction 由霍爾狀態的轉移對在每個邊緣更新（src/HallScan_V2_1.c : 130）。遇到不合法的轉移（跳狀態）時它維持原值不變，所以不會因為雜訊亂跳。
靜止抖動不會誤鎖。車輪停在霍爾邊界來回時，方向會一正一反交替，上面的「方向一致 → 計數歸零」就會把計數清掉，因此不需要額外的防彈跳時間。

3可調參數（全部在 src/userparms.h）

3-1. 主旋鈕：要倒退多少才鎖

src/userparms.h : 279

#define EMB_ROLLBACK_REV_EDGES 3        // 目前 = 3，倒退 5.2 mm

這是唯一一個平常需要動的參數。覺得太靈敏（正常騎乘被誤鎖）就加大；覺得倒溜太多才鎖就縮小。

設定值倒退距離佔車輪感受
11.7 mm1/365極靈敏，只要動一格就鎖（不建議，容易被量測抖動誤觸）
23.5 mm1/183很靈敏
3 目前5.2 mm1/122幾乎察覺不到就鎖住
47.0 mm1/91
814 mm1/46約一節手指
1628 mm1/23明顯感覺到退了一下
4579 mm1/8約 8 cm
91159 mm1/4規格上限，不能再大
超過 91 會編譯失敗，不會靜默放行。護欄在 src/userparms.h : 283~287： 
#define EMB_HALL_EDGES_PER_WHEEL_REV ((HALL_EDGES_PER_REV * GEAR_RATIO_X100) / 100)
#define EMB_ROLLBACK_MAX_EDGES (EMB_HALL_EDGES_PER_WHEEL_REV / 4)
#if (EMB_ROLLBACK_REV_EDGES) > (EMB_ROLLBACK_MAX_EDGES)
#error "EMB_ROLLBACK_REV_EDGES 超過 1/4 車輪 (91 邊緣) 的倒溜上限規格"
#endif
上限由極對數與齒比自動推導，換馬達或改齒比時會自己跟著變，不必手改。

3-2. 什麼情況才啟用偵測

src/userparms.h : 278

#define EMB_ROLLBACK_CMD_THRESHOLD 500  // 0.35 km/h 的命令

速度命令要大於這個值，才認為「駕駛確實要走」而啟用偵測。低於它就解除武裝（那屬於無動力倒溜，交給 Plan B）。一般不需要動；調高會讓輕踩油門時不受保護。

3-3. F/R 切換的誤鎖防護

src/userparms.h : 299

#define EMB_ROLLBACK_FLIP_HOLDOFF_MS 300   // 0 = 停用

方向切換只允許在車速 ≤ 1.0 km/h 時發生（src/longwin/codeSw.h : 90），但切換後車可能還在以 ≤1 km/h 往舊方向滑 —— 這在偵測邏輯看來就是倒溜，會立即鎖定並閂鎖。這個抑制窗就是為此存在。

命令符號變化是否抑制為什麼
0 → 前進（或 0 → 後退）不抑制這就是上坡起步的情形，必須立即偵測
前進 → 後退（或反之）抑制 300 ms給滑行中的車一點時間停下來，避免切檔就被鎖

若實機測試切 F/R 時仍會被鎖，把時間加大（例如 500 ms）。想確認這個防護有沒有在作用，設成 0 再測一次對照。

3-4. 附加閘門（預設停用）

src/userparms.h : 294

#define EMB_ROLLBACK_MIN_PULSES 0       // 0 = 停用（預設）

要求 HallPulsesLatch（每 100 ms 的霍爾邊緣數）達到此值才允許鎖定。

設成非 0 會破壞 1/4 車輪的規格保證。它等於重新加上一個「最低倒溜速度」的限制：
設定值1235
最低倒溜速度0.0630.1260.1890.315 km/h
比這更慢的潛行倒溜將永遠不會觸發鎖定（例如 0.1 km/h 時，5.7 秒就走完 16 cm 了）；而且該值每 100 ms 才更新一次，會多出最多 100 ms 的延遲。
保留這個旋鈕只是為了：若實機出現極低速抖動造成的誤鎖，可以用它把那個來源排除掉。用完建議調回 0。

4鎖定之後會發生什麼

① 電磁煞車夾住，馬達同時斷力
O_EM_BRAKE_CTRL 拉低，同一時間呼叫 MotorStallForceOutputZero()（main.c : 1421）， 所以馬達不會頂著煞車繼續出力。
② 閂鎖：油門還踩著也不會放開
狀態進入 LOCKED 並設定 s_bRollbackLatched（src/longwin/s_logic_embraker.c : 103~108）。 LOCKED 狀態平常會做「運轉前檢查 → 放開煞車」，但閂鎖的守衛擋在最前面，所以坡上油門仍踩著時不會被放開又倒溜。
③ 解除條件：駕駛鬆油門
油門回到門檻以下才解閂，之後回歸正常流程。沒有自動解除、沒有計時解除。 要在坡上重新起步，必須先鬆油門再重試。
這是刻意的設計。若鎖定後自動放開，坡上會出現「鎖→放→又倒溜→鎖」的來回擺動。代價是上坡起步若每次都會微幅倒退，駕駛就得反覆「鬆油門重試」—— 若實測覺得干擾太大，先加大 EMB_ROLLBACK_REV_EDGES（給馬達更多時間建立扭力），而不是取消閂鎖。

6症狀 → 該調哪裡

症狀調整
上坡起步一給油門就被鎖住，完全起不來 加大 EMB_ROLLBACK_REV_EDGES（例如 3 → 8，允許倒退 1.4 cm），給馬達時間建立扭力。不要動閂鎖邏輯
倒溜太多才鎖縮小 EMB_ROLLBACK_REV_EDGES
平路正常行駛偶爾被鎖 ① 先用 scope 確認 g_u8EmbRevEdgeCnt 是否真的在累加；② 若是極低速時發生，暫時把 EMB_ROLLBACK_MIN_PULSES 設 2~3 驗證來源；③ 檢查霍爾相序與 uGF.Direction 是否正確
低速切前進/後退就被鎖加大 EMB_ROLLBACK_FLIP_HOLDOFF_MS（300 → 500）
完全不會鎖 ① 確認 CODESW_EMBRAKER_ENABLE = 1（src/longwin/codeSw.h : 32）；② 確認 EMB_ROLLBACK_MIN_PULSES = 0；③ 確認命令有超過 EMB_ROLLBACK_CMD_THRESHOLD；④ scope 看 g_u8EmbRevEdgeCnt 是否卡在 0（方向偵測有問題）
鎖定瞬間有頓挫／異音 屬正常 —— 這是緊急保護，會同時夾煞車與斷力。若要更柔和只能讓它更早介入（縮小 N），在車速更低時就鎖

8附錄：為什麼改成用「邊緣數」

2026-07-31 之前的做法要同時滿足三個條件才開始計時，再持續 2 秒才鎖：

舊條件值問題
倒溜速度 >= Q15(0.02)0.45 km/h慢速潛行倒溜永遠不觸發
HallPulsesLatch >= 30.19 km/h該值每 100 ms 才更新，額外延遲
持續 EMBRAKER_ROLLBACK_LOCK_MS2000 ms光是這 2 秒就能滑掉數十公分

只把 2 秒改小沒有用 —— 速度門檻還在，慢速倒溜依然抓不到。改用「連續 N 個反向霍爾邊緣」之後，條件變成純位移，與速度脫鉤，才能寫出「不超過 1/4 車輪」這種可驗證的規格。
