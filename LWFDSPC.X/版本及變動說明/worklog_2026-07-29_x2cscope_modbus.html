LWFDSPC Worklog: X2CScope / Modbus Debug

Project: Longwin_LWFDSPC_V0.1 / LWFDSPC.X  |  Date: 2026-07-29  |  Result: Scope View fixed

1. 問題現象 SYMPTOM

X2CScope 可以連線，Watch View 正常，但 Scope View 會跳出 Invalid Block ID。

關鍵對照條件：

  • MODBUS enabled: Watch View OK，Scope View error。
  • MODBUS totally disabled: X2CScope Watch View / Scope View 都正常。

這表示 UART2 實體連線與基本 X2C protocol 不太像是主因，問題更像是 Modbus 啟用後破壞了 X2CScope 的內部狀態。

3. 根因 ROOT CAUSE

Modbus raw register buffer 採用「Modbus register address 直接當 array index」的寫法，但原本陣列長度沒有預留 index 0，造成最高 register address 越界。

例子

LCD register range: 0x0001 - 0x0011
Code access:        u16Regs[0x11]
Required length:    0x12 words, valid index 0..0x11

Old layout:         17 words, valid index 0..16
Out of bounds:      u16Regs[17] == u16Regs[0x11]

PC-GUI 也有同樣問題：最高使用 u16Regs[0x1D]，所以需要 0x1E words。Battery decode 使用到 u16Regs[0x09]，也需要 0x0A words。

此越界只在 Modbus enabled 且資料被 encode/decode 或 register map task 寫入時出現，因此症狀與「關掉 Modbus 後 X2CScope 正常」完全吻合。

4. 修改內容 FIX

Modbus buffer size / indexing

src/longwin/s_modbus_master.h

Battery raw: u16Regs[0x0A]  // valid Modbus addresses 0x0001-0x0009
LCD raw:     u16Regs[0x12]  // valid Modbus addresses 0x0001-0x0011
PC-GUI raw:  u16Regs[0x1E]  // valid Modbus addresses 0x0001-0x001D

Battery register map pointer

src/longwin/s_modbus_master.c

{SLAVE_ID_BATTERY, 0x0001, 9, E_MODBUS_DIR_READ,
 &g_stModbusAllData.uBatteryData.u16Regs[0x01]}

Initial LCD write state machine

初次 LCD write 送出後，加入 siCurrentMapIndex = i;，避免等待回應時用錯 task 解析 response。

Mirror helper bounds

src/longwin/s_modbus_decode.c

modbusDecode_getMirroredValue() / setMirroredValue() 改成依 device 選對應 buffer 與實際長度，不再用 LCD struct size 推算所有 device offset。

5. X2CScope 節奏調整 TUNING

diagnostics/diagnostics_x2cscope.c

#define X2C_TX_FIFO_SIZE 512u
#define X2C_TX_FIFO_READY_MARGIN 96u
#define X2C_COMM_MAX_CALLS_PER_PASS 24u
  • 每圈 main loop 最多呼叫 X2CScope_Communicate() 24 次。
  • 若 TX FIFO free space 小於 96 bytes，提前停止本圈 X2C communicate。
  • X2CScope_Update() 仍在 ADC ISR 嘗試執行；若剛好正在 Communicate()，就 skip 一次，避免 library re-entry。

這不是主要根因修正，但可避免 X2C 背景通訊長時間霸住主迴圈，降低 Scope View 在大量資料時的壓力。

8. 後續觀察項

  • 長時間測試 10-30 分鐘：Scope View enabled + Modbus enabled。
  • g_u16ModbusGuardErrorCount 必須維持 0。
  • g_u16X2cTxFifoDropCount / g_u16X2cRxFifoDropCount 必須維持 0。
  • g_u16X2cUpdateSkipCount / g_u16X2cUpdateCount 建議長時間低於約 10%。
  • 若之後想加快 Scope View，可以試 X2C_COMM_MAX_CALLS_PER_PASS = 32 或 48；若穩定優先可降到 16。
