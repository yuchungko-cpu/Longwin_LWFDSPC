7-1. V0.20 新增下坡滑動偵測（EMB_DOWNHILL_*）

情境：坡上停著點一下油門再立刻放掉 → EMB 釋放、車被重力拉走、命令已歸零。此時 三條既有路徑全部不通：① UVW 短路制動力 ∝ 轉速，ω≈0 時幾乎為零；② 速度環 reference=0 時「零誤差＝零扭矩」， 滑得越慢越沒力；③ 倒溜偵測結構上看不到往前滑（見第 5 節紅框）。→ 只剩 1000 ms failsafe，屆時車速已高。
作法：命令歸零後仍移動達門檻 → EMB 立即上鎖。此時動能極小，不適感最低。

7-2. V0.20Speed 量測修正（無參數，但影響本節多項行為）

移除了 CNRead_Inline() 內的 else if (HallPeriod <= HallMinPeriod) Speed = 32767;
HALL_MIN_PERIOD = 434 是 SPEED_FS_RPM(12000 馬達RPM) 對應的 Timer1 週期，而 12000 ≈ 2.96 × MOTOR_MAX_RPM。所以該分支只在量到「馬達物理上限 3 倍轉速」時觸發 —— 物理上不可能，只可能是停車顫動或接點彈跳。把不可能的取樣轉成「最大確信的極端值」就是缺陷本身。 刪除後沒有 else，Speed 自然保持前值，這才是無效取樣該有的處理。

它是三個症狀的共同根因，前兩個過去都只是被繞過：
症狀32767 如何造成
堵轉放開後倒行 1m+ CalculateParkAngleHall() 的 abs(Speed) <= Q15(0.02) 低速分支刻意不依賴方向 （內層 if/else 兩邊完全相同），因為近零速時方向由顫動決定、不可信。32767 讓這道防護失效 → 改走內插 → 電流向量最多錯置 120° → 扭矩反向。過去用 bStallReleaseCoast 關 PWM 圍堵
UVW lock 鎖不上過去改用 HallPulsesLatch 取代 Speed 圍堵
堵轉保護失效
（讀碼推論，待實車確認）		 bClearlyMoving = abs(Speed) >= Q15(0.06) 因 32767 恆為真 → 釋放計數器 500ms 後把堵轉計數歸零 → 顫動時永遠累積不到 8 秒 → 降流與 60 秒閂鎖都不啟動。
可驗證的預測：修正後頂牆超過 8 秒應首次出現推力明顯變小，60 秒後停止出力
⚠ 上述兩道圍堵（bStallReleaseCoast、UVW_LOCK_STOP_PULSES）刻意保留當縱深防禦， 不要因為此修正就簡化它們 —— 等實車驗證過再談。
