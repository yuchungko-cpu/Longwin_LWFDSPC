1. 根因判定:coast 與 UVW 進鎖的訊號域不一致ROOT CAUSE

main.c(V0.23) 停車鏈:UVW 進鎖判斷 · coast 閂鎖 · PWM 輸出分支

兩個機制搶同一個時機,車速條件相同、命令條件不同

命令條件成立時機動作
coastTargetRpm == 0放油門瞬間 六個開關全關(OVRDAT=0 / OVREN=1),並每個 50 µs pass 清三個積分器
UVW 短路ReferenceRAW == 0 減速斜坡走完,最多晚約 700~800 ms(曲線 2 = R30/2ms + τ64ms + 100 count 吸零) 三相下橋全開(OVRDAT=1),有制動力

兩者的車速閘門都是 HallPulsesLatch < UVW_LOCK_STOP_PULSES(4)。於是 「放油門後、斜坡還沒走完就已近停」會落進一段 PWM 全關、零制動 的窗口。

死結如何形成

  • bStallReleaseCoast 帶了 uGF.UVWLock == 0 → 只要 UVW 進不去,就一直停在全關那一支。
  • 零制動下車因路面微傾斜或殘餘動量以 0.2~0.5 km/h 潛行 → HallPulsesLatch 回不到 4 以下 → UVW 永遠進不去。
  • V0.23 起 coast 是閂鎖(退閂只有「重新給油門」或「UVW 生效」)→ 也出不來。
  • 只剩 EMBRAKER_LOCK_TIMEOUT_MS(1500 ms) failsafe 帶速夾停 = 回報的震動, 而「感覺 UVW lock 沒啟動」字面上就是事實。
為何 V0.22 沒有此症狀:V0.22 的 coast 沒有閂鎖,latch 一升過 4 就退出全關, FOC 以 reference 0 繼續制動把車真正停住 → UVW 接手。V0.23 為修上坡震動把它改成閂鎖, 平路就少了這條收尾制動;當時 commit 假設「平路單調減速故不受影響」,該假設在微傾斜路面不成立。
進一步發現:bStallReleaseCoast 本身就是「UVW 進鎖用錯訊號」的補丁 —— 它要守的空窗(頂牆/堵轉放開後、近停但 UVW 還沒短路)之所以存在,正是因為堵轉時命令很大、 ReferenceRAW 要走完整條斜坡才歸零。把進鎖改看油門目標後,該空窗直接消失。

馬達現在只有兩種通電狀態:FOC 或 UVW 三相短路。PWM 全關只剩三個系統理由:

條件為什麼保留
uGF.RunMotor == 0未運轉,含 IBKS(手剎車/充電中)按下 —— 充電時不可短路馬達
uGF.Fault == 1故障閂鎖(過流/霍爾異常/60 秒堵轉)—— 故障的橋不該短路

uGF.Coast 仍有寫入者(bMotorStop、堵轉歸零、VR 失效路徑)但已無讀取者; 欄位保留並在 control2.h 標註退役理由。

V0.23 的上坡震動不會回來:那個震動的機制就是 coast 反覆進出 (PWM 開關 + 每次清三個積分器造成扭矩階躍)。coast 移除後 FOC 連續運作,倒溜時 error = 0−(−v) = +v 會平順地抵抗,不再有階躍。
相依性:本設計依賴 CODESW_UVW_LOCK_ENABLE == 1 —— 短路分支是「馬達不要出力」的唯一實作者。若為除錯關掉 UVW lock,就只剩「命令歸零」一層。 已在程式註解標明。

5. 修正:下坡偵測判準改為「週期必須真的變短」FIX

main.c · CNRead_Inline() · userparms.h 的 EMB_DOWNHILL_NODECEL_*

舊判準的缺陷(獨立於項目 3,但同樣貢獻平地頓挫)

「週期沒變長(或變長不到 1/2S)就算沒減速」不是速度無關的。把它換算成減速度,隱含門檻是

a_th = v² / (2^TOL_SHIFT × d_LOOKBACK)      d_LOOKBACK = LOOKBACK × 1.75 mm

分子是 v²,車速愈高門檻愈鬆。以 S=6、LOOKBACK=24(d=42 mm)計:

車速a_th對平路阻力估 0.2 m/s² 的關係
0.97 km/h0.027 m/s²餘裕 7 倍,安全(舊註解只驗算過這一點)
2.0 km/h0.115 m/s²餘裕縮小
3.0 km/h0.257 m/s²已超過阻力估值 → 平路被判成「沒減速」

→ 平路在 2.6~3.0 km/h(恰在 3 km/h 上限以下)自由滑行時會誤觸,而且下坡偵測走硬夾。

修正

- (HallPeriod > EMB_DOWNHILL_MIN_PERIOD) &&
- ((HallPeriod <= u16Old) ||
-  ((uint16_t)(HallPeriod - u16Old) <= (uint16_t)(u16Old >> EMB_DOWNHILL_NODECEL_TOL_SHIFT)))
+ (HallPeriod > EMB_DOWNHILL_MIN_PERIOD) &&
+ (u16Old > HallPeriod) &&
+ ((uint16_t)(u16Old - HallPeriod) >= (uint16_t)(u16Old >> EMB_DOWNHILL_NODECEL_TOL_SHIFT))
  • 維持原檔案「先比大小再相減、全程留在 16-bit」的紀律。
  • TOL_SHIFT 語意由「容忍變長」變成「必須變短的最小量」(純雜訊裕度),值仍 6(1.6%)。 調整方向與 V0.23 速查表相反,已在文件標警示。
  • 自由滑行阻力恆為正 → 平路/上坡週期必然變長 → 任何車速、任何阻力下結構上都不可能觸發 (這才是註解一直宣稱、但舊寫法並不成立的性質)。
坡度(24 邊緣基線,起點 0.97 km/h)週期變化判定
平路+14%不觸發 ✔
2%(阻力與重力打平)≈ ±0%不觸發 → 退回 failsafe 保底(約 1 km/h,衝擊小)
5%−13%觸發 ✔(對 1.6% 裕度有 8 倍餘裕)
10% / 20%−27% / −43%觸發 ✔

巨集與計數器沿用 V0.21 的 NODECEL 命名以維持與客戶調校表的對應,語意變更已在各處註明。

s_logic_embraker.c/.h · logic_embraker_getLastLockReason() · main.c 的 LOCK 分支

實車無法即時觀測,故做成「事後可讀」的累計值(RAM,斷電歸零;空載台架可用 X2CScope 即時看)。 十個回傳 LOCK 的分支全部記錄原因,計數器只在 LOCK 的上升緣累加 (FAULT 與倒溜閂鎖每個 20 ms tick 都會回傳 LOCK,不擋掉會灌爆計數器)。

變數意義
g_u8EmbLockReason最後一次的原因碼:1 = UVW+延遲(正常停車)、2 = failsafe、 3 = 下坡滑動、4 = 倒溜、5 = Plan B、6 = IBKS、7 = 倒溜閂鎖保持、8 = 故障、9 = 運轉前檢查

8. 審視:控制器過溫(未修改,等客戶規範)REVIEW

溫度分區電流上限比例行為
< 53°CNORMAL0.35(≈16 A)無限制
53 / 58 / 63 / 68 / 73°CLEVEL 1~50.33 / 0.31 / 0.291 / 0.273 / 0.254 只降電流,車照跑(爬坡無力、重載極速略降)

所以「直接停」只發生在 ≥78°C,且不是減速到 0,而是扭矩瞬間歸零 + 機械煞車硬夾 —— 沒有減速斜坡、沒有軟夾、也沒有車速閘門。煞停完全靠機械硬夾。

待客戶確認規範時要一起討論的三點:

  • 73°C(12 A)到 78°C(0 A + 硬夾)之間只有 5°C,沒有跛行回家階段。
  • 過溫夾煞是全系統最粗暴的路徑(硬夾、無車速閘門),而客戶本次抱怨的正是帶速夾煞震動; EMB_SOFT_CLAMP_TICKS 的軟夾刻意排除了 bMotorStop。
  • 限流過程對外完全無提示:bControllerIsOverLoad 有寫入但無讀取者, A05 上報那兩行被註解掉(s_logic_temp_controller.c:158-159), Modbus 的 bMotorOverload 永遠是 0。駕駛體感是「先莫名沒力,再突然剎停」。
順帶發現的既有缺陷(與規範無關,尚未修): bMotorStop 期間 EMB 狀態機被整段跳過(if (bMotorStop) 硬夾; else { 狀態機 }), 狀態凍結在 RELEASED。溫度恢復後若駕駛還握著油門,RELEASED 分支對該組合沒有動作 → 沒有人發出 RELEASE → 機械煞車保持夾住,同時電流上限恢復 → FOC 對著夾緊的煞車出力堵轉 (8 秒後電流砍半、60 秒後閂鎖)。要脫離必須放掉油門一次。 電池保護走同一條路,症狀相同。修法:bMotorStop 硬夾時把 EMB 狀態強制成 LOCKED (同 IBKS 分支的作法,其註解本就寫明要避免「硬體被鎖住卻沒有任何分支負責解鎖」)。
